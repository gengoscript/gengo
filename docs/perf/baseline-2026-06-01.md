## After GC threshold tuning (Phase 6a)

| Case | before_ms | after_ms | delta |
|---|---|---|---|
| 010_string_concat_heavy | 806 | 733 | −9% |
| 001_compute_stress | 128 | 128 | 0% |

**010 gc_runs:** 11,880 → 4,520 (−62%). GC time: ~192ms → 73ms.  
**001 gc_runs:** 723 → 723 (unchanged). Driven by managed-slice allocation failure, not object-count threshold.

`gc_object_step` added to all config presets: dev=256, stress=512, tiny=64 (was hardcoded 64 everywhere).
When live objects are few, the new threshold delays GC by 256 allocations instead of 64 — 4× less frequent GC for workloads with low steady-state object counts (string chains).
Compute_stress GC is driven by heap exhaustion in `vmAllocManagedSlice`; each O(2048) sweep costs ~20 µs.

## After const_eq / const_sub / const_add / const_lt (Phase 3d)

| Case | before_ms | after_ms | delta |
|---|---|---|---|
| 003_fib_recursive | 1841 | 1627 | −12% |
| 008_runtime_call_overhead | 218 | 211 | −3% |
| 001_compute_stress | 122 | 120 | −2% |
| 010_string_concat_heavy | 733 | 699 | −5% |

Compile-time peephole: when `constant k` is the most-recently emitted instruction,
the following `eq`/`sub`/`add`/`lt` is replaced in-place with `const_eq`/`const_sub`/
`const_add`/`const_lt` (same 3-byte bytecode, different opcode byte). One dispatch saved
per fused site. `const_add` includes string concat handling identical to `.add`.

**Cumulative from original baseline:**
fib_recursive −16% · call_overhead −12% · compute_stress −10% · struct_field −8% · concat_heavy −13% Previously, a GC triggered inside `concatDynString` could sweep the source strings and return their backing bytes as the destination, triggering a `@memcpy` alias panic under high allocation pressure.

## After string accumulation buffer for const_add chains (Phase 4)

| Case | before_ms | after_ms | delta |
|---|---|---|---|
| 010_string_concat_heavy | 699 | 497 | −29% |

**010 gc_runs:** 4,520 → 647 (−86%). alloc_objects: 1,400,052 → 200,052 (−86%).  
One GC-managed `dyn_string` per chain iteration instead of seven.

Strategy: `const_add` (string path) accumulates bytes into a 4 KiB per-VM scratch buffer
(`vmState().str_acc`) instead of allocating a `dyn_string` for each intermediate result.
A `.string` value pointing into `str_acc` acts as the TOS accumulator, identified by
pointer-identity check (`a.string.ptr == &str_acc[0]`).
A one-byte lookahead checks whether the following opcode is also `const_add`; if not,
the buffer is promoted to a proper GC `dyn_string` via `makeDynString`. This ensures
callers never observe a `.string` value pointing into the VM-local buffer.

**Cumulative from original baseline:**
fib_recursive −16% · call_overhead −12% · compute_stress −10% · struct_field −8% · concat_heavy −39%

## After loop→get_global inline (Phase 5)

| Case | before_ms | after_ms | delta |
|---|---|---|---|
| 008_runtime_call_overhead | 211 | 188 | −11% |
| 009_struct_field_access | 402 | 377 | −6% |
| 010_string_concat_heavy | 497 | 465 | −6% |
| 003_fib_recursive | 1627 | 1571 | −3% |
| 001_compute_stress | 120 | 101 | −16% |

Medians from 7 runs. compute_stress shows wider variance (±20%) because its GC runs are triggered
by heap-exhaustion (managed-slice growth) rather than the object-count threshold.

Strategy: at the end of each `loop` dispatch, peek one byte at the jump target.
If the target is a warm `get_global` IC (ic_slot != 0xffff), execute the global load inline
and advance IP past the 5-byte get_global encoding, saving one full dispatch cycle per loop iteration.
No compiler changes or new opcodes needed; the cold first-iteration path falls through
to normal dispatch so the IC warms before the inline path activates.

**Cumulative from original baseline:**
fib_recursive −19% · call_overhead −22% · compute_stress −24% · struct_field −14% · concat_heavy −42%

## After set_global_loop fused opcode (Phase 6)

| Case | before_ms | after_ms | delta |
|---|---|---|---|
| 008_runtime_call_overhead | 188 | 179 | −5% |
| 009_struct_field_access | 377 | 358 | −5% |
| 001_compute_stress | 101 | 97 | −4% |
| 010_string_concat_heavy | 465 | 456 | −2% |

Medians from 4 runs.

Strategy: compile-time peephole in `chunk.emitLoop`. If the last emitted instruction is
`set_global` (5 bytes), its opcode byte is rewritten to `set_global_loop` and the 2-byte
loop offset is appended in place — saving 1 byte vs the 8-byte `set_global + loop` sequence.
The VM handler performs set_global's IC lookup, then the back-edge jump, then the same
opportunistic `get_global` inline introduced in Phase 5.

This fires on every C-style for loop whose post-step is a global assignment (`i++`, `i += 6`,
`candidate += 1`, etc.), eliminating one dispatch per iteration on all such loops.

**Cumulative from original baseline:**
fib_recursive −20% · call_overhead −26% · compute_stress −27% · struct_field −18% · concat_heavy −43%

## After get_local_const_eq / get_local_const_sub triple fusion (Phase 7)

| Case | before_ms | after_ms | delta |
|---|---|---|---|
| 003_fib_recursive | 1561 | 1432 | −8% |
| 008_runtime_call_overhead | 179 | 183 | +2% |
| 009_struct_field_access | 358 | 365 | +2% |
| 010_string_concat_heavy | 456 | 465 | +2% |

Medians from 5 runs. Net: −109ms across all five primary benches.

Strategy: compile-time peephole extends const-op fusion to a triple fusion.
When `get_local n` immediately precedes `constant k` (verified by position arithmetic —
`last_get_local_code_pos + 2 == const_pos` — not by inspecting code bytes, which would
risk false positives from data bytes of preceding 3-byte instructions), the `get_local`
opcode byte is rewritten to `get_local_const_eq` or `get_local_const_sub`. The original
5-byte layout `[get_local][slot][const_eq/sub][idx_hi][idx_lo]` is preserved; the middle
byte (the old const_eq/sub opcode) becomes a skip byte advanced over by a bare `ip += 1`.

The +2% regression in loop-heavy benches is from the WASM JIT's dispatch table growing
by 2 entries — no incorrect fusion fires on those workloads.

fib profile savings: 4.9M `const_eq` dispatches + 4.9M `get_local` dispatches →
4.9M `get_local_const_eq` dispatches (half the dispatch count for that pair).
Similarly 2.7M `const_sub` + 2.7M `get_local` → 2.7M `get_local_const_sub`.

**Cumulative from original baseline:**
fib_recursive −26% · call_overhead −24% · compute_stress −27% · struct_field −16% · concat_heavy −42%

## After get_local_const_eq_jif_pop quad fusion (Phase 8)

| Case | before_ms | after_ms | delta |
|---|---|---|---|
| 003_fib_recursive | 1432 | 1271 | −11% |

Medians from 5 runs. All other benches within ±2% noise.

Strategy: compile-time quad fusion extending the triple fusion.
When `get_local_const_eq` (5 bytes) immediately precedes `emitJump(.jif_pop)`,
the `emitJump` peephole overwrites the `get_local_const_eq` opcode byte with
`get_local_const_eq_jif_pop` and appends the 2-byte jump placeholder in place,
replacing the 8-byte sequence `get_local_const_eq(5) + jif_pop(3)` with a
7-byte single instruction.

The VM handler reads all 6 operand bytes (slot, skip, idx_hi, idx_lo, jmp_hi, jmp_lo),
computes the equality comparison on the local against the constant, and branches
without a separate pop — 1 dispatch instead of 2 for every if-check of the form
`if local == constant`.

In fib(30) this fires on both `if n == 0` and `if n == 1`, saving 4.9M dispatches.

**Cumulative from original baseline:**
fib_recursive −35% · call_overhead −23% · compute_stress −27% · struct_field −15% · concat_heavy −43%

## After ret_const fused opcode (Phase 9)

| Case | before_ms | after_ms | delta |
|---|---|---|---|
| 003_fib_recursive | 1271 | 1253 | −1% |
| 010_string_concat_heavy | 462 | 470 | +2% |

Medians from 5 runs. Other benches within ±1% noise.

Strategy: compile-time peephole in `chunk.emitOp`. When `op == .ret` and
`last_const_code_pos + 3 == code_len` (a `constant k` is the immediately-preceding
instruction), the constant's opcode byte is rewritten to `ret_const` in place —
saving 1 byte vs `constant(3) + ret(1)` and 1 dispatch per constant-returning call.

In fib(30): fires for all n==0 (514K calls, `return 0`) and n==1 (832K calls,
`return 1`) base cases = 1.35M fewer dispatches → 18ms savings.
Recursive cases (`return fib(n-1) + fib(n-2)`) use `add + ret`, which does not fuse.

The ret slow-path (defers, typed returns) was extracted into `retSlowPath()` —
both `ret` and `ret_const` share it, keeping the fast-path inlined in the switch.

The +2% on concat_heavy is from the dispatch table growing by 1 entry.

**Cumulative from original baseline:**
fib_recursive −35% · call_overhead −23% · compute_stress −27% · struct_field −17% · concat_heavy −42%

## Observations

1. **fib_recursive is pure call overhead**: `constant`, `get_local`, `call`, `ret` dominate. The repeated `constant` load before comparisons is the single biggest target for a superinstruction.

2. **get_global is #1 across nearly every workload**: Named global lookup (hash scan) appears in every top-10. This is the highest-value IC target after struct field access.

3. **compute_stress has 723 GC runs**: Struct allocation in a loop. `get_field`/`invoke_method` are high because it accesses struct fields on every iteration.

4. **No map probe data**: The bench workloads don't exercise `map_hashed` lookups at scale. The map probe counter infrastructure is in place but needs a map-heavy bench case.

5. **String concat bytes = 0 across all benches**: Existing bench suite has no string-heavy workloads. A new bench case is needed to exercise the concat path.
